# 환각 감사: 생성된 단어 콘텐츠에 실재하지 않는 영어 단어

**대상** NGSL 2,801개 항목 (qwen3:14b Q4_K_M, Ollama 배치 생성)
**시점** 2026-08-25, 문형 백필 완료 직후
**결과** 실재하지 않는 영어 단어를 학습자에게 제시한 항목 **13건** — 전부 교정 완료

---

## 왜 이 문서가 있는가

이 앱은 학습자에게 "이건 이렇게 씁니다" 라고 **가르친다**. 챗봇이 틀리면 대화가 어색해지고
말지만, 교재가 틀리면 학습자가 틀린 것을 외운다. 그래서 생성된 콘텐츠의 거짓은
품질 문제가 아니라 결함이다.

그리고 이건 프롬프트로 못 막는다. 프롬프트를 고치면 환각의 **비율**은 낮아지지만
0 이 되지는 않는다. 이미 생성된 유한한 집합에서 확인된 거짓을 지우는 일은
재생성(확률적)이 아니라 교정(결정적)으로 해야 한다 — 재생성은 같은 자리에
**다른** 거짓을 넣을 수 있다. 그래서 손으로 고쳤고, 무엇을 왜 고쳤는지 여기 남긴다.

## 어떻게 찾았는가

LLM 을 쓰지 않았다. 환각을 LLM 으로 검사하면 검사기도 환각한다.

1. `usage_note` 의 **따옴표 안 영어**, `example` 전체, `pattern` 의 영어 조각, 그리고
   `confused_with` 의 모든 항목에서 영어 토큰을 뽑았다 — distinct 4,004개.
2. 각 토큰을 **WordNet** 에 조회했다. 굴절형은 `morphy` 로 되돌리고, WordNet 이
   담지 않는 기능어(the, of, although …)와 축약형은 허용 목록으로 걸렀다.
   WordNet 은 CLAUDE.md §3.5 가 교차 확인용으로 지정한 공개 자원이다.
3. 남은 후보를 **사람이 하나씩 원문과 함께 읽고** 판정했다.

후보는 `usage_note`·`example`·`pattern` 에서 47건, `confused_with` 에서 36건.
그중 실제 환각은 13건이었고 나머지는 오탐이었다.

### 오탐이 왜 그렇게 많은가

WordNet 은 **내용어 사전**이다. 다음은 전부 실재하는데 WordNet 에 없어서 걸린다.

| 유형 | 예 |
|---|---|
| 기능어·접속사 | `although`, `whereas`, `unless`, `whether`, `whilst`, `via`, `toward` |
| 부정대명사 | `something`, `everyone`, `anybody`, `everything` |
| 약어·상표 | `app`, `pdf`, `usb`, `qr`, `whatsapp`, `etc` |
| 고유명사 | `kim`, `rowling`, `harpercollins` |
| 토큰화 찌꺼기 | `ing`(`+ -ing` 에서), `adj`, `ly`, `caf`(café), `doesn`/`didn`(축약형) |

**그래서 이 검사는 자동 판정에 쓸 수 없다.** 후보를 좁히는 데까지만 쓰고
마지막 판정은 사람이 한다. 4,004개를 13개로 좁힌 것이 이 도구의 값어치다.

### 세 갈래로 나뉜다

**(1) 지어낸 파생어 — 6건.** 가장 뚜렷한 생성 패턴이다. 모델이
*"X는 [품사]로만 쓰이고, [다른 품사]로는 'X+접미사'가 있어요"* 라는 문형을 쓰려다,
그 자리에 넣을 단어가 없으면 **만들어 넣는다.**

```
restaurant → restaurate     kitchen → kitcheny
fact       → factful        analysis → analysist
cultural   → culturalist    increasingly → growingly
```

문장 틀이 먼저 정해지고 내용이 그 틀을 채우는 방식이라, 틀이 요구하면 없는 것도 나온다.
**표제어에 접미사를 붙인 꼴이면서 사전에 없는 토큰**은 기계적으로 찾을 수 있다.

**(2) 외국어 혼입 — 3건.** `oranje`(네덜란드어), `ayer`(스페인어), `luft`(독일어).
qwen3 는 다국어 모델이고, 한국어로 영어를 설명하는 이중 언어 과제에서 제3의 언어가
샌다. 같은 뿌리로 `confused_with` 에 한자가 그대로 들어온 것도 있다 —
`minority → '少数'`, `rice → 'rice饭'`.

**(3) 철자 오류 — 3건.** `habor`, `solt`, `sault`. 그냥 오타로 보이지만,
`habor` 는 *"'구두'를 의미하는 'habor'"* 라는 **뜻까지 지어내** 붙였다.
오타에서 시작해 그 오타의 의미를 만들어낸 것이라 (1)과 성격이 같다.

**(4) 비표준형 — 1건.** `respirate` 는 respiration 에서 거꾸로 만들어진 드문 형태로,
표준형은 `respire` 이고 그나마 의학 문맥에서 쓴다. 존재 자체를 부정할 단어는 아니지만
A1 학습자에게 breathe 의 비교 대상으로 제시할 단어는 아니다.

## 존재 검사가 못 잡는, 더 큰 문제

없는 단어보다 **훨씬 큰 문제**가 따로 있다. 단어는 전부 실재하는데 **주장이 거짓**인 경우다.
WordNet 조회로는 하나도 안 걸린다.

`usage_note` 에 품사·가산성을 단정하는 문장이 **156건**("명사로만" 119 · "불가산" 37) 있다.
그중 8개를 읽었더니 6개가 사실과 달랐다.

| 항목 | 저장된 설명 | 문제 |
|---|---|---|
| `name` | "'name'은 명사로만 쓰이고, 동사 'to name'과는 다릅니다" | 한 문장 안에서 자기모순. name 은 동사다 |
| `center` | "'Center'는 명사로만 쓰이고" | center 는 동사다 |
| `process` | "명사로만 쓰고 동사로는 'process'가 아니라 'process'를 동사로 쓸 수 없어요" | 문장이 깨졌고 내용도 틀렸다 |
| `history` | "동사로는 'historic'처럼 변형되어" | historic 은 형용사다 |
| `adviser` | "'상담사'처럼 불가산명사예요. 'a adviser'는 잘못" | adviser 는 가산명사다 |
| `abroad` | "'abroad'는 명사로만 쓰이고" | abroad 는 부사다 |

같은 항목 안에서 **문형 칸과 설명 칸이 서로 모순**하는 경우도 있었다.

- `analysis` — 문형 `"불가산명사 (an analysis X)"` vs 예문 `"...did an analysis of..."`
- `salt` — 설명 "'a salt'는 틀리고" vs 문형 `"a/the + salt"`

둘 다 교정에 포함했다. 그리고 이 부류는 **기계 검사가 된다** — 아래에 구현했다.

## 품사 단정 검사 (선별기에 상설)

위 부류를 사람이 매번 눈으로 잡을 수는 없어서 선별기에 규칙으로 넣었다.
`app/content/lexicon.py` 가 WordNet 품사 태그를 조회하고,
`app/content/screening.py` 가 설명의 단정과 대조한다.

**주장은 셋으로 나뉘고, 각각 다르게 다룬다.**

| 검사 | 심각도 | 무엇을 하는가 | 건수 |
|---|---|---|---|
| `pos_claim_wrong` | 🟡 medium | 주장한 품사가 사전에 **아예 없다**. 단순화가 아니라 거짓이다 | 2 |
| `pos_claim_overreach` | ⚪ low | "…로만" 인데 다른 품사도 있다. 교육적 단순화일 수 있어 낮춘다 | 47 |
| `countability_claim_unchecked` | ⚪ low | 가산성을 단정했다. **판정이 아니라 호출이다** | 45 |

`pos_claim_wrong` 이 잡은 둘이 정확히 사람이 눈으로 찾았던 것과 같다.

```
abroad   'abroad' — 명사라고 했는데 사전에는 형용사·부사 뜻만 있어요
culture  'culture' — 동사로 안 쓴다고 했는데 사전에 동사 뜻이 있어요
```

### 판정하지 않기로 한 것들

**한국어 주어.** "한국어 '이점'은 명사로만 쓰이지만" 은 한국어에 대한 말이라
영어 사전으로 반증할 수 없다. 실제 데이터에 20건 있었고 전부 건너뛴다.
인용된 **영어** 토큰이 주어일 때만 판정한다.

**사전에 없는 단어.** `parts_of_speech` 는 모르면 `None` 을 준다. `None` 과
빈 집합은 다르다 — 이 구분이 무너지면 WordNet 에 없는 기능어·약어가 전부 결함이 된다.

**가산성.** WordNet 에 가산성 정보가 **아예 없다.** 그래서 판정하지 않고 사람에게 넘긴다.
이 45건이 Wiktionary 를 붙일 가장 큰 이유다.

### 재현율을 택했다

SemCor 태깅 빈도가 있는 뜻으로만 좁히면 모순 판정이 48건에서 30건으로 줄어 조용해진다.
그런데 그때 빠지는 것에 `team`(team up), `golf`, `burden`, `reference` 처럼
**진짜 오류가 섞여 있었다.** 이 모듈은 승인하지 않고 순서만 매기므로 오탐 비용이
미탐 비용보다 낮다. 그래서 거르지 않는다.

### 사전이 없어도 돌아간다

nltk 나 코퍼스가 없으면 `lexicon.available()` 이 False 가 되고 품사 대조는
조용히 꺼진다 — 사전이 없다고 검수 UI 가 못 뜨면 안 된다. 다만 **가산성 호출은
사전이 필요 없으므로 그때도 계속 뜬다.** 검사가 통째로 사라지면 없는 줄도 모른 채 지나간다.

코퍼스는 런타임이 아니라 **이미지에 굽는다**(`Dockerfile`). 런타임 다운로드로 두면
오프라인 환경에서 검사가 조용히 꺼진다.

## 남는 이야기

속도보다 정확도를 택하는 게 맞다.

## 덧붙임 (2026-08-27) — 해석 검수가 되돌려 준 7건

위 13건은 **사전으로** 찾았다. `manual_fixes.yaml` 에 나중에 붙은 7건은 경로가 다르다.

예문 해석(`example_ko`)을 사람이 읽고 고친 32건(`gloss_fixes.yaml`)을 넣으면서,
교정본에도 배치의 자동 검사 4종을 돌렸다. 사람이 고친 해석인데 7건이
`reject_unrelated_gloss` 에 걸렸다 — "해석에 이 낱말의 뜻이 남아 있지 않다".

열어 보니 **틀린 쪽은 해석이 아니라 저장된 뜻이었다.**

| 표제어 | 저장돼 있던 `meaning_ko` | 고친 뜻 |
|---|---|---|
| `squid` | 감자전(물고기 종류) | 오징어 |
| `straw` | 스티로 소프트한 줄기 (종이로 만든 줄기) | 빨대 |
| `tuna` | 타우나, 생선 종류 | 참치 |
| `sushi` | 회 (생선 등 생선으로 만든 음식) | 초밥 |
| `outlet` | 전원 공급 장치, 플러그 | 콘센트 (벽에 있는 전기 구멍) |
| `coleslaw` | coleslaw (샐러드 종류) | 코울슬로 (양배추 샐러드) |
| `chewy` | 물이 잘 안 빠지는 | 쫄깃한, 질긴 |

이건 이 문서가 다루는 "지어낸 영어 낱말"과 종류가 다르다. `squid` 도 `tuna` 도
실재하는 낱말이고 철자도 맞다. 거짓은 **그 낱말에 대한 한국어 주장** 쪽에 있었다
(`straw` 만 `confused_with: [styro]` 로 없는 영어 낱말까지 끼고 있었다).
위에서 "더 흔한 결함은 실재하는 단어에 대한 거짓 주장이고 아직 사람이 봐야 한다"고
적어 둔 그 156건이 이런 모양이다.

한 가지 방법이 생겼다. `reject_unrelated_gloss` 는 해석과 뜻이 **한 조각도 안 겹치는지**만
보므로, 둘 중 **하나를 사람이 보증하면 나머지 하나의 탐지기가 된다.** 사람이 읽은
해석 32건을 잣대로 넣었더니 틀린 뜻 7건이 걸려 나왔다. 전수 검수 없이 뜻을 훑는
길이 하나 열린 셈이다 — 다만 해석을 먼저 읽어야 하므로 공짜는 아니다.
